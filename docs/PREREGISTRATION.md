# Preregistration and Analysis Plan

Status: current operational preregistration. This document preserves the original estimand while documenting post-generation operational corrections needed for valid inference.

## 1. Research question

Controlling for deterministic structural plan quality, do LLM judges systematically favor LLM-generated training plans over programmatically generated plans, and does this effect vary by judge model family, model size, rubric, or whether the plan matches the judge's own family?

## 2. Hypotheses

### H1: Source preference

LLM judges will choose LLM-source plans more often than programmatic-source plans after matching on source-neutral structural plan quality.

### H2: Judge-family heterogeneity

The LLM-source preference may vary by judge family and model size.

### H3: Self-family preference

Judges may prefer plans generated by models from their own family, but this is a hypothesis to test, not an assumption.

### H4: Rubric heterogeneity

Preference effects may differ across rubrics such as goal coherence, caution/safety, actionability, explanation quality, and overall preference.

## 3. Experimental units

The primary unit is a matched pair consisting of:

- one LLM-source training plan
- one programmatic-source training plan
- same fixture cell or equivalent matching strata
- similar source-neutral structural quality

Each pair is evaluated in both left-right orders, across repeated runs and judge models.

## 4. Generated and retained corpora

The current retained candidate pool is:

- 192 Qwen-source LLM plans.
- 192 Gemma-3-source LLM plans.
- 384 total LLM-source plans.
- 640 programmatic control plans.
- 1024 total matching-pool candidates.

All retained corpora must pass integrity gates before matching:

- expected plan and provenance counts
- expected fixture-cell coverage
- missing sidecar check
- JSON validity check
- seven-day plan length check
- structural prompt leakage check
- human-facing contradiction check
- title/session consistency check
- duplicate/session-signature audit

The current programmatic corpus passed the artifact-integrity gate with 640 plans, 32 cells, and 20 plans per cell.

## 5. Matching-score correction

An initial matching attempt using the old TrailTraining quality score produced only 30 matched pairs. The score distribution suggested source contamination:

- LLM plans mostly scored near 97-100.
- Programmatic plans mostly scored around 30.
- Programmatic plans had passed structural/artifact audits.

Therefore the old TrailTraining quality score must not be used as the primary matching score unless tests prove it is invariant to presentation/prose-only changes.

Primary matching must use a source-neutral structural score.

The structural score may use:

- session type sequence
- duration and weekly load
- active-day count
- rest-day count and spacing
- hard-day count and spacing
- long-run presence/count
- quality-session presence/count
- readiness/recovery/race-phase appropriateness
- deterministic structural violations

The structural score must exclude:

- title wording
- workout prose richness
- purpose prose richness
- explanation/rationale length
- citations
- claim attributions
- data-note verbosity
- source model name
- generation arm
- file naming artifacts

## 6. Matching criteria

Primary matching should require, by default:

- same fixture cell
- same athlete band
- same readiness category
- same recovery capability category
- same race phase
- same style
- same plan length

Within each stratum, match by:

- structural-score tolerance
- weighted structural feature distance
- no reuse of programmatic candidate unless explicitly designed as with-replacement sensitivity analysis

The target is at least 250 matched pairs, preferably 256.

If 250 structurally valid pairs cannot be achieved under same-cell matching, the limitation must be documented and a preregistered fallback must be chosen before judge evaluation. Full judging must not be launched with an invalid low-coverage match.

## 7. Judge-evaluation volume

The full study requires at least 10,000 judge-facing evaluation documents.

Required formula:

```text
250 matched pairs x 2 left-right orders x 5 repeated runs x 4 judge models = 10,000 evaluation documents
```

Preferred formula:

```text
256 matched pairs x 2 orders x 5 runs x 4 judge models = 10,240 evaluation documents
```

The old 30-pair match would produce only:

```text
30 x 2 x 5 x 4 = 1,200 evaluation documents
```

It is invalid for the full study.

## 8. Judge-facing masking and randomization

Judge-facing artifacts must:

- hide generation arm
- hide source model family
- hide file names and source identifiers
- standardize presentation format as much as possible
- randomize left/right order
- record order assignment in metadata only
- preserve source-family metadata outside judge-facing content for analysis

## 9. Primary outcomes

Primary outcome:

- judge chooses LLM-source plan over programmatic-source plan

Secondary outcomes:

- rubric-level LLM-source win rate
- win rate by judge model
- win rate by judge family
- win rate by source family
- self-family match effect
- order bias
- score-gap sensitivity
- fixture/band subgroup differences

## 10. Statistical analysis

Report descriptive and inferential results:

- overall LLM-source win rate
- confidence intervals, preferably bootstrap or binomial intervals as appropriate
- per-judge and per-rubric win rates
- order-bias audit
- self-family preference analysis
- mixed-effects or clustered logistic model when sample size supports it

Candidate model:

```text
outcome: judge chooses LLM-source plan
fixed effects: source family, judge family, self-family match, rubric, order, structural score gap
random effects or clustering: pair id, fixture cell, judge model
```

Do not overclaim if matched-pair count, judge count, or source-family balance is limited.

## 11. Robustness checks

Run and report:

- excluding high score-gap pairs
- excluding duplicate-heavy fixture cells
- stratifying by band A1/A2/A3/A4
- stratifying by source family Qwen/Gemma
- stratifying by judge family
- order-swap consistency
- style/prose length imbalance sensitivity
- rubric-specific analysis

## 12. Launch gates

Full judge evaluation is allowed only if all are true:

1. Structural-score implementation has tests.
2. Structural score is invariant to prose-only changes.
3. Matching produces at least 250 valid pairs, preferably 256.
4. Pair coverage across cells and source families is documented.
5. Structural score gaps are within a defensible tolerance.
6. Matched structural features are balanced.
7. Style/leakage audit passes.
8. Judge-facing artifacts are source-masked and left-right randomized.
9. Launcher confirms at least 10,000 evaluation documents.

## 13. Reporting rules

The final report must distinguish:

- generated plans
- retained candidate plans
- matching-pool candidates
- matched pairs
- judge-facing pair/order documents
- repeated-run documents
- valid judgment records after schema filtering

Do not claim the study satisfies the 10,000-document criterion unless at least 10,000 judge-facing evaluation documents were actually attempted under the accepted matched-pair set.

## 14. Threats to validity

Known threats:

- Equal structural score is not full equality.
- Presentation leakage can remain even after masking.
- Programmatic plans may use an LLM explainer for narrative fields.
- Structural score design may encode researcher assumptions.
- Judge models may have family/style familiarity.
- Local inference constraints may limit model families and sizes.
- Duplicate/session-signature filtering can reduce effective diversity.
- Generated plan corpora are specific to the training-plan domain.

All limitations must be reported transparently.
